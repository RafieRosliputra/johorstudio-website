Website Handover Guide

Everything you need to keep johorstudio.com running day to day: adding projects, updating the site, and what not to touch. Written for someone who is comfortable with computers but is new to this setup.

1. What this is

The website is a set of static pages. Pages are built from a GitHub repository, and then served by a small web server on the home server (TrueNAS). Project photos are added by copying folders to a network share. The Webmaster panel turns those folders into website pages.

1. Project folderPhotos + project.md, copied to the website-uploads share
2. WebmasterPublish projects turns folders into pages
3. Websitejohorstudio.com shows the new pages
A. Code changeMade on GitHub or on your Mac, then merged into main
B. UpdateWebmaster pulls main and publishes again
C. WebsiteNew design or text goes live

2. Daily tasks

Add a new project

  1. On your Mac, open the website-uploads share. Create a folder named YYYYMMDD Event name, for example 20261103 Event name. Use the event date.
  2. Copy the photos into the folder. Common formats are JPG, PNG, WebP, HEIC and TIF. Keep the originals as they are; the panel makes the web versions.
  3. Add a project.md file. It has key-value lines at the top (title, date, client, services, cover photo), then the description in one or more paragraphs. Copy an existing project.md from _DONE as a template.
  4. Open the webmaster panel. The folder appears under New folders. Check the photo count and that the project.md is found.
  5. Press Publish projects. Wait for the status to show Finished with Done. N project(s) live.
  6. Open the website and check the new project page. The folder has moved to _DONE.
If a folder does not show up Folders starting with _ or . are ignored on purpose. Rename it so it does not start with _.

Update the website after a code change

  1. Make the change on a branch (for example webmaster-something), commit it and push the branch to GitHub.
  2. Merge the branch into main and push main. Do not skip this, because Update only reads main.
  3. If the change touches tools/admin.py (the webmaster itself), restart the webmaster app in TrueNAS (Apps, webmaster, Restart) first. Otherwise the old code keeps running.
  4. In the panel, press Update from GitHub and publish. The status should say Already up to date or pull the new commits, then Done.
  5. Check the website. If something looks wrong, tell the person who made the change; do not edit files on the server.

Change the home page carousel order

The home page carousel is set in the HERO list in tools/build.py. The first item is shown first. Change the order there, run tools/build.py so that site/index.html is rebuilt, commit both files, merge into main, then Update.

Remove a project or one photo

In the panel, under On the website, use Remove project or open Photos and use Remove photo. The original files are moved to a folder named _Project name in website-uploads, so nothing is lost. Those _ folders are the originals; keep them unless you have a backup.

Edit the other pages

Use Open Silex editor from the panel. Silex is a visual editor for pages that are not project pages. Make the change, publish from Silex, then check the website.

3. Photo rules

The panel processes photos automatically, so you do not need to resize them yourself.

RuleWhat happens
FormatConverted to WebP
QualityWebP quality 50. Smaller files, loads faster, still sharp on screen
Size capPhotos over 24 megapixels are scaled down to 24 megapixels
WatermarkThe logo watermark is added to the full and normal sizes. Thumbnails are not watermarked again
Existing photosPhotos processed with older settings are redone once, the next time the site is published
Watch out Do not put a watermarked photo in the folder. Use the original photo, or the watermark will be added twice.

5. Behind the scenes (TrueNAS and backups)

You do not need to run these every day. This section explains what exists, so you know what is safe to touch.

Storage layout

/mnt/ssd/website/uploadsThe website-uploads share, including _DONEYes. Only empty _DONE should be cleaned, and only with a backup
/mnt/ssd/website/silexData for the Silex editorYes
/mnt/ssd/scriptsSnapshot script snap-website.shYes. Used by the daily cron job

Snapshots (automatic)

The dataset ssd/website is snapshotted by a script. A cron job runs it every day at 03:00. The script only takes a new snapshot when 14 days have passed since the last one. Once the new snapshot is confirmed, it deletes the older ones and keeps the two newest. That means there are always about one month of snapshots. Snapshots do not include the uploads share, which is its own dataset.

To see snapshots: TrueNAS web UI, Datasets, ssd/website, Snapshots. To restore one file from a snapshot, use the Guide page.

Full backup (manual)

A full tar copy of repo, uploads and silex is made by hand using the command in the Guide page. Keep copies outside the TrueNAS server. Snapshots are on the same disk, so they do not protect against the disk failing.

Git history on the server The repo on the server was made shallow (one commit). Full history is still on GitHub, so nothing is lost.

6. Golden rules

  • Do not edit files in repo on the server. Publish rewrites the site folder, so manual changes are lost, and they are not on GitHub.
  • Check before you Update. On the Guide page, run Check repo status. If files other than site/ have changed, stop and ask.
  • Make changes on GitHub, not on the server. Use a branch, then merge into main.
  • Restart the webmaster app after a change to tools/admin.py.
  • Never delete the newest snapshot. Never run a rollback unless it is an emergency and you have made a fresh copy first.
  • Do not delete _ folders in website-uploads unless you have a backup. They are the originals of removed projects.
  • Never share passwords in chat or in this guide. Keep them in a password manager.

7. Open items

These are known gaps. Tick them off as they are done.

Off-site copy. Snapshots and tar files are on the same server. Set up a copy of the project folders and repo/media to another disk or cloud storage.
Check that Publish can move folders. The admin container mounts website-uploads as read-only in the compose file. Publish has worked so far, but confirm that folders still move to _DONE after any change to the setup.
Contact page mismatch. The service list in tools/build.py does not match the committed site/contact.html. Decide which one is correct, then rebuild.
Hero images. The photo rules (quality 50, 24 MP cap) apply to project and portfolio photos, not to the hero images on the home page.
Old portfolio thumbnails. Small portfolio thumbnails were made before quality 50 was set. Regenerating them is optional.
Server password. The TrueNAS root password was shared in a chat during setup. Change it, and store the new one in a password manager.
Old branches. webmaster-timezone-kl and webmaster-guide were merged into main. They can be deleted on GitHub.
Access list. Confirm which emails are allowed through Cloudflare Access for the webmaster panel, and give the new person access if needed.
